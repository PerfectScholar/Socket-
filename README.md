# Python TCP Socket 終極密碼

使用 Python 3 標準函式庫，不用另外安裝套件。伺服器隨機選出 1～100 的答案，客戶端讓玩家輸入猜測。一次只有一位玩家，猜中就結束；沒有回合限制或猜錯即輸的規則，輸入 q 可以中途離開。

## 啟動方式

將 server.py、client.py 放在同一個資料夾，開啟兩個終端機，都切換到這個資料夾。

1. 第一個終端機執行：
   ```sh
   python server.py
   ```
2. 第二個終端機執行：
   ```sh
   python client.py
   ```
3. 輸入整數後按 Enter，依提示繼續猜。輸入 q 離開，也可以按 Ctrl+C。

如果 Windows 的指令是 `py`，將上述 `python` 換成 `py`。預設使用本機 `127.0.0.1:5000`。若連線失敗，先確認伺服器已啟動；若連接埠被占用，可以將兩個檔案的 PORT 一起改成另一個相同的數字。

伺服器在猜中、玩家離線或發生網路錯誤後結束。要再玩一次，重新啟動 server.py 和 client.py。

## 協定

所有訊息使用 UTF-8，每一則以換行字元 `\n` 結尾。下表為一整行的內容，表格省略最後的換行。

| 方向 | 範例 | 意義 |
| --- | --- | --- |
| 伺服器 → 客戶端 | `READY 1 100` | 遊戲開始，目前可猜 1～100 |
| 客戶端 → 伺服器 | `40` | 猜 40 |
| 伺服器 → 客戶端 | `HIGHER 41 100` | 答案更大，目前可猜 41～100 |
| 伺服器 → 客戶端 | `LOWER 41 69` | 答案更小，目前可猜 41～69 |
| 伺服器 → 客戶端 | `CORRECT 55` | 猜中，答案為 55，遊戲結束 |
| 伺服器 → 客戶端 | `INVALID 41 69` | 格式錯誤或超出目前範圍，範圍不變 |

上下界都包含端點。上述回覆是格式示例，實際數字依答案與猜測改變。空白行、文字、小數、超出範圍或重複已排除的數字都會收到 INVALID。整數前後空白會被忽略。無效 UTF-8 也回覆 INVALID。收到沒有換行的資料時會繼續等，若對方此時斷線，就丟棄未完成的那一行。

## 我理解的 Socket
作業過程:https://chatgpt.com/share/6ad4d2d0-aab4-83e8-bb6b-17e20c6546eb
Socket 是程式收送網路資料的介面。這個專案使用 TCP：伺服器先 bind 指定位址和連接埠，再 listen 等待連線；accept 接受連線後取得與玩家通訊的 Socket。客戶端用 connect 連到伺服器。

TCP 傳的是連續的位元組，不會替應用程式保留訊息邊界。一次 sendall 送出的內容，可能分成好幾次才收到；好幾次傳送也可能一起到達。所以不能把一次 recv 當成一則訊息。這裡用換行當分隔，並用 makefile("rb") 和 readline() 讀到完整的一行。底層即使拆包或合包，也能按行解析。先收完整一行再 decode，可以避免 UTF-8 字元剛好被拆開的問題。

sendall 會持續送出直到資料全部交給系統，或發生例外；它不代表對方已經處理完訊息。readline 回傳空位元組代表對方已關閉傳送方向。with 會在結束時關閉資源，網路錯誤則由例外處理顯示訊息。

答案與上下界由伺服器保管。客戶端只顯示提示、取得輸入並傳送，因此是否猜中、輸入是否合法，都以伺服器判斷為準。

## 可以向老師展示

- 同時啟動兩個程式，輸入數字，觀察範圍縮小，直到出現「猜中了」。
- 輸入 `abc`、`3.5`、空白行、`0`、`101` 或已排除的數字，觀察 INVALID 且範圍不變。
- 客戶端輸入 q，伺服器會顯示玩家離線並結束。
- 關閉伺服器，客戶端會在下一次讀取或傳送時顯示斷線或連線錯誤。

本專案是課堂用的本機、單人、逐回合遊戲，沒有多人、資料庫或額外框架。

## 實測紀錄

已在 localhost 實際啟動獨立的 server.py 與 client.py，完成隨機答案的遊戲並確認猜中後結束；也測過非法輸入、q 離開及未啟動伺服器時的連線錯誤。
